# Special cargo code challenge

In this challenge, you are going to interface with a platform that provides transport pricing information to prospective customers. This pricing info is based on shipment quotes provided by many freight forwarding and transportation companies. Prices depend on many factors, but in this challenge we'll focus on route (origin/destination), company and date.

Imagine that many freight forwarding companies send you their price for a sea freight shipment of a standard 20' container with destination Rotterdam from one of five origin ports. The price info will include the originating port as well as the effective date. Collecting and aggregating this pricing info over time will allow you to provide prospective customers with the lowest rate for their inquiry over all forwarding companies.

## The challenge

Given a series of objects that describe shipping prices from a certain origin location, your goal is to provide upon request an _expected rate_ for all known locations. The expected rate is defined as the average of the prices of the 10 cheapest shipping companies for that origin location.

For example, if you receive:

- Company 1 offers shipping from Shanghai for $2000
- Company 2 offers shipping from Ningbo for $1500
- Company 3 offers shipping from Shanghai for $1700

Then the expected output should be:

- Expected rate for Shanghai: $1850
- Expected rate for Ningbo: $1500

The input is provided by a test application that sends JSON objects by HTTP POST requests to http://localhost:3142. After each 1000 objects sent, the test application will send a GET request to the same URL to fetch the latest expected rates. The details of the input & output are described below.

### Input

The input is generated by the test application binary ([`./client`](..)). The test application will start sending POST requests immediately after starting the application. After each request it will wait for a response with status code `200` before continuing. It will send a total of 1,000,000 objects.

The objects are valid JSON objects with four values:

- `Company` (integer): identifier for a company, in range 1-999 (inclusive)
- `Price` (integer): price, in range 1-99999 (inclusive)
- `Origin` (string): 5-character origin location code, one of: `"CNSGH"` (Shanghai), `"SGSIN"` (Singapore),`"CNSNZ"` (Shenzhen), `"CNNBO"` (Ningbo), `"CNGGZ"` (Guangzhou)
- `Date` (string): first date that the given price is in effect, formatted `YYYY-MM-DD`

Some examples:

```
{"Company":807,"Price":239,"Origin":"CNSGH","Date":"2018-04-10"}
{"Company":95,"Price":806,"Origin":"SGSIN","Date":"2018-07-06"}
{"Company":405,"Price":30,"Origin":"CNGGZ","Date":"2020-05-24"}
{"Company":601,"Price":814,"Origin":"CNSGH","Date":"2019-02-27"}
```

You can assume that the input data is always well-formatted and within the ranges as indicated. You may receive multiple prices for the same forwarder-origin combination; they are not sorted in chronological order. You can assume that a forwarder provides a consistent price per origin for a specific date (e.g. 1700 dollars for Ningbo per 2020-11-23).

### Output

After each 1000 objects received, your application will receive a GET request to retrieve expected rates. The rates should be calculated separately for all origins.

Your output should be a valid JSON object with origin location codes as keys and applicable expected rate as values. If there is no data for some origin, do not include that origin. The average should be based on all the data received so far and calculated from the 10 lowest prices for that origin. Only one price per company per origin should be considered. Averages should be rounded down to the nearest integer number.

For example:

```
{"CNGGZ":948,"CNNBO":1892,"CNSGH":2615,"CNSNZ":1618,"SGSIN":3029}
```

The above output means:

- For Guangzhou (`CNGGZ`), the average price for the ten forwarders with lowest rates was $948.
- For Ningbo (`CNNBO`), the average price for the ten forwarders with lowest rates was $1892.
- For Shanghai (`CNSGH`), the average price for the ten forwarders with lowest rates was $2615.
- For Shenzhen (`CNSNZ`), the average price for the ten forwarders with lowest rates was $1618.
- For Singapore (`SGSIN`), the average price for the ten forwarders with lowest rates was $3029.

If multiple prices for a company-origin combination are provided, you should only consider the price with the latest date. For example, if you receive a Singapore price from company 123 for January 1, 15 and 23 of 2021, only the one at January 23 should be used as part of the average in the expected rate. The other prices should no longer be used in any average after the January 23 price is received.

## Your application

The challenge was designed to be doable in any language you prefer. You are encouraged to implement it with little (preferable no) use of third-party libraries, with the exception of JSON and HTTP libraries if they are not available as standard libraries for your language. If you decide to add additional libraries to the project, please write a small paragraph to help us understand your choice.

Similarly, use whatever build tool you prefer (if the language requires a build tool).

Be aware that the main languages used at Special Cargo are JavaScript (frontend; Vue framework) and PHP / Moodle (backend), and we do not intend to deviate from that in the near future. We are happy to accept any language of your preference for this challenge, because we want to see what you come up with in a language that you are comfortable with. That said, if working with JavaScript or PHP does not appeal to you in any way, a developer position at Special Cargo might not be a good fit.

## Testing the solution

You can verify your solution by:

1. Start your application;
2. Start the test application.

```
./client
```

3. Wait until the test application exits. As it is running, it will report how your rates compare to the rates calculated by the test application.

The test application can be further configured with these flags:

- _-i_ (int): Values to send before each price index retrieval (default 1000)
- _-n_ (int): Total number of quotes to send (default 1000000)
- _-h_ (string): Hostname to connect to (default "localhost")
- _-p_ (int): Port to be used for connection (default 3142)
- _-par_ (int): Number of requests to send in parallel (default 1)
- _-s_ (int): Seed to produce fixed i/o randomized values
- _-simple_: Use simple terminal output (no colors/unicode)

Feel free to test your solution with different parameter sets.

## Assessment criteria

We expect you to write a solution that is production-ready. The code should be well-factored, without needless repetition, and be automatically built & tested. Your code will be assessed by 2 software developers in our company.

We would like to see a solution that:

- is correct (it passes the tests, and has no obvious failures on border conditions);
- is readable (things are properly named, objects & functions have a clear responsibility);
- is testable (there are unit tests);
- is scalable (is it easy to adapt the solution to deal with much more input).

We are also interested to see what documentation you provide.

And above all: good luck and have fun! We are very curious to see what you come up with!
